# 最终方案

## 1 定位

一个去 AI 味的工程，不是一个靠模型自注意力执行的 skill。它由三部分组成：

- **引擎**：Python 包加 CLI，负责保护、扫描、核验、打包判定输入、生成报告。所有能定位、能计数、能比对的工作都在这里。
- **薄 skill**：给宿主模型读的路由文件和规则卡片，每次只加载与本次命中相关的几条。
- **数据**：规则 YAML、词表、阈值、体裁强度表、eval 用例、人写语料。

规则内容本身（前一版合并出来的判断层）不动，只改它的存放形式和执行方式。

## 2 仓库结构

```
maybe-humanizer/
  doc/              本套文档
  rules/            规则 YAML，唯一真相源，schema 在阶段 1 原型之后定
  lexicons/         中英词表、阈值、体裁强度表（YAML）
  engine/           Python 包
  skill/            生成物：SKILL.md 路由、规则卡片、范例；供 Claude Code 等宿主安装
  docs-generated/   生成物：给人读的规则手册、conflicts、来源与许可
  evals/            结构化用例、运行器、基线记录、留出样本
  corpus/           人写语料及人工标注
```

生成物不手工编辑。规则 YAML 改了，重新生成 skill/ 和 docs-generated/。

## 3 三种工作模式

| 模式 | 触发 | 交付 |
|---|---|---|
| 审稿 | "看看哪里像 AI""帮我看看问题" | 裁决后的问题清单，不重写全文，不打分，不判断作者身份 |
| 改写 | "改""重写""润色""去 AI 味""校对" | 改写稿加自动生成的改动说明与残留清单 |
| 就地改文件 | 点名一个文件要求就地修改 | 句子级补丁写回文件，加简短报告 |

改写力度按用户措辞分三档：改写（可重建结构）、润色（只调句序和拆并句）、校对（只改错字病句）。编辑范围分三档：structural（默认，可删整句空话、合并相邻事实句）、bounded（不合并不重排，整句空话进待确认清单交用户）、in-place（一句不删，改动全在句内）。中文公开写作长文默认 bounded。用户指定的优先。

## 4 流水线

代码编排，模型在三个位置出场。每一步的输入输出格式见 03-formats.md。

### 4.1 准备（代码）

1. 判断文件类型。源代码、配置、结构化数据停手。
2. 凭证门检。出现密码、API key、私钥、会话 cookie 时停，只回一句请删除后重试。
3. 整块内容占位：代码块、行内代码、URL、frontmatter、表格、命令、报错原文。记映射表。数字、日期、版本、引语、限定条件留在正文里，模型看得见。
4. 全文按句编号。中文按句末标点（。！？）切，英文按 .!? 加空格切，编号从 1 开始，编号跨段连续。
5. 抽两张表。逐字项：命令、数字与单位、日期、版本号、专名、英文品牌名。语义项：否定词、命题限定词（可能、大概、尚未、might、seems、not confirmed）。每项记所在句号。
6. 分诊。形式线索定体裁：不到 300 词带话题标签是社交帖；有代码块或接口引用是技术长文；有称呼加募资措辞是商务邮件；分步说明或 README 结构是文档；都不命中落通用长文。用户措辞定力度与范围。输出一行声明，不提问。只在疑似虚构文本或凭证时停下。
7. 短文门槛：中文少于 80 字、英文少于 40 词时，审稿模式只列具体命中，不给整体判定。

### 4.2 扫描（代码）

词表与正则出候选，每条带句号、规则 id、一行判据、一行修法，编号 F1…Fn。同时出统计：字数、句数、句长分布、破折号数、引号样式分布、全半角混用、加粗数、emoji 数、话题标签数、隐藏字符。

扫描结果是候选，不是结论。阶段 1 原型此步为空。

### 4.3 诊断与裁决（模型，第一次调用）

输入：编号正文（占位后）、分诊声明、候选清单、命中规则的卡片。

任务：
1. 对每个候选给三档之一：确认、排除（说明落在哪条通过条件）、待确认。
2. 通读全文，补出扫描找不到的问题：段落可互换、空洞论证、假想反方、现造术语、结论超出证据、同义反复。编号 S1…Sm。
3. 同一句命中多条时合并成一个编辑任务。

审稿模式到此交付：确认项和待确认项分块列出，与出处相关的命中和纯写作建议分开，默认不超过六条，每条写问题类型、触发句、建议动作、建不建议改。结论只用四种：命中模式 N 处、无需编辑、已授权改写、不确定。

### 4.4 改写（模型，第二次调用）

输入：编号正文、裁决后的清单（确认项与待确认项）、四条轴、五条保护铁律、一个与当前模式匹配的端到端范例。

五条保护铁律：不新增原文没有的事实、数字、例子、观点、来源；不丢原文有的信息和限定；不把不确定改成确定，不把相关改成因果；不动逐字项和作者的声口；不为显得像真人添加原文没有的第一人称、幽默、感受。

输出：
1. 句子级补丁。in-place 与 bounded 只允许句内改与句间明确标注的动作；structural 与改写档可整篇生成，但仍按句号对应。
2. Markdown 台账：每个编号写"已改"或"保留"加理由。缺编号即失败。
3. 模型自己发现的新问题追加编号。

### 4.5 核验（代码）

硬失败，退回 4.4，最多三轮，每轮只回传失败项：

- 受保护片段还原后与原文逐字不一致。
- 逐字项缺失。
- 台账缺编号。
- 越过授权范围：in-place 句数变化；bounded 出现未列入清单的合并或删除；校对档出现结构改动；润色档重排段落。
- 补丁引用了不存在的句号，或重建后文本无法拼接。

复核信号，标黄不退回，交给 4.6 和报告：

- 语义项计数变化（命题限定词减少、否定词变化）。
- 因果标记新增（因为、导致、because、due to）。
- 第一人称、emoji、破折号、感叹号新增。
- 字数低于原文 85%，句数变化超过 10%（in-place 和 bounded 下）。
- 复扫：对照 4.2 清单报告哪些候选仍在、哪些是改写新引入的。新引入多于清掉的记为信号。

### 4.6 语义判定（模型，第三次调用，独立）

对象：所有字面改过的变更块，按句号区间对应原文，支持一对多、多对一、纯删除，带前后各一句上下文。structural 模式另读一遍全文，查首末段是否对应、段落顺序是否损害论证、引用标识是否仍紧跟它支持的陈述。

每个变更块做七项核对：范围、条件、否定、情态、完成态、方向、强度。输出：通过、失真（写明哪一项）、需作者确认。

失真项阻断交付，回 4.4 一轮；仍失真则标为需作者确认并交付阶段稿。

### 4.7 交付（代码）

从台账和 diff 自动生成：改动说明（改了什么、为什么、保留了什么）、残留清单（哪条规则、哪句、为什么没改）、前提声明（体裁判定依据、用了谁的词表、哪个机械步骤没跑）、轮数。规则 id 由代码填。两份说明合计不超过六条，多出的进附录。

## 5 规则数据

每条规则的字段：id、语言、类别（protection / process / pattern / genre / measurement / optional）、判据、修法、通过条件、已知会漏掉什么、正反例、检测器定义（可空：词表、正则、计数，含参数）、严重档 `severity`、语料命中频率 `frequency`（可空，阶段 2 之后填）、各体裁强度（标准 / 放宽 / 加严）、来源与裁决记录。后两个排序字段是 Plus 和 Air 版本的依据，见 05-editions.md。

给模型的卡片只含判据、修法、通过条件、已知会漏掉什么、一组正反例。来源与裁决记录只进给人读的文档。

先只卡片化有检测器的规则；其余按 id 按需读原文。schema 在阶段 1 原型之后定。

## 6 evals 与阻断

用例字段见 03-formats.md。三类样本：最小编辑样本（原真人原文，只允许标点级改动）、事实不漂移样本、套话应清理样本，另有模式与档位样本。

CI 阻断项：

- 受保护片段被改。
- 逐字项缺失。
- 台账缺编号。
- 越过授权范围。
- 最小编辑样本出现标点以外的改动。
- 必须消失项仍在。
- 语义判定确认的失真（阻断并标记人工复核）。

只记录不阻断：自然度评分（模型判官）、复核信号、成本与轮数。

留出样本：另备一批未参与开发的样本，基线和每个阶段都在同一批上跑，运行条件（模型版本、温度、prompt 版本）固定并记录。

## 7 误报率

误报的定义：命中了，但按该条通过条件不该动。落在术语、引语、代码、作者在讨论这个词本身、体裁固定表述。人写语料上的命中率不是误报率，旧文章里照样有套话。

语料：中英文各二三十篇，优先 2022 年 11 月前的博客、技术文档、公众号文章，确认获取权限。每篇人工标注扫描候选"该不该改、为什么"。扫描器进入改写步骤的门槛是这份标注上的误报率有数，而不是命中率低。

## 8 阶段与完成定义

| 阶段 | 内容 | 完成定义 |
|---|---|---|
| 0 | 固定前一版 skill 的版本与运行条件；准备留出样本；跑原版基线，按漏检、漏处理、误改、越界四类记录；修四处契约矛盾；重跑得修正版基线 | 两份基线数据入库 |
| 1 | 原型，只覆盖中文短文与 Markdown：准备、诊断裁决、句子级补丁改写、台账、核验、变更块语义判定、自动报告。不接扫描器，不迁移规则，用少量代表规则跑通 | 台账编号零缺失；逐字项零丢失；与两份基线在同一批样本上对照，误改与越界有下降证据。达不到就改原型 |
| 2 | 扫描器与词表 YAML；收人写语料并标注；量误报率，校准通过条件；只卡片化有检测器的规则；定 schema，导入其余规则；SKILL.md 路由加三种模式各一个范例 | 漏检相对阶段 1 下降；误报率有数且有标注支撑；skill/ 可安装 |
| 3 | 英文；structural 模式全文连贯性；长文分节；补中文词表；MCP | 按需，每项不破坏已有阻断项 |

## 9 授权边界

先做阶段 0 和阶段 1 原型。原型只覆盖中文短文与 Markdown。暂不全量迁移规则、不补上游词表、不做 MCP、不做长文并行。用阶段 1 的对照结果决定阶段 2 怎么做。

## 10 降级路径

没有引擎时，SKILL.md 要求模型：自己按句编号，自己列编号清单，自己填台账，交付时声明"未经机械校验"。它只保证列了的都处理了，不承诺别的。

## 11 后续更新

- 版本：现在做的是 Max。Plus（模型自主编排的 skill）和 Air（放进 CLAUDE.md 的浓缩提示词）的定义在 05-editions.md，共用同一个规则来源，Max 阶段 2 之后再排。

- 上游来源变化：前一版仓库的 upstream-monitor 继续监控 59 个来源，新条目只作为词表或规则候选进入 rules/，走同一套裁决。
- 词表更新：改 lexicons/ 的 YAML，跑 evals，通过后重新生成 skill/。
- 规则变更：改 rules/，重新生成卡片和文档，evals 通过才合并。
- 阈值：凡是继承来的数值（85%、10%、每千词一处、一千字分界）在本仓库自己的语料上测过之前，说明里写明未经验证。
