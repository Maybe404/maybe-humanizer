# 去 AI 味（Max 版路由）

这个 skill 是一条流水线的入口，不是一份要你逐条背的规则集。能定位、能计数、能比对的工作都在引擎里；你只在三个位置出场：诊断裁决、改写、语义判定。每一步的输入输出格式固定，引擎会核验你的输出，缺编号、丢逐字项、改了受保护片段、越过授权范围都会被退回。

## 有引擎时

引擎命令是 `humanizer`（仓库根目录 `uv run humanizer`）。工作目录默认 `.humanizer/`。

1. **准备**：`humanizer prepare <文件或 -> --request "<用户原话>"`。它做凭证门检、文件类型门检、占位、按句编号、抽逐字项和语义项、分诊，并打印一行分诊声明和编号正文。返回码 2 表示停手（凭证或非散文文件），把打印的那一句原样回给用户，不做别的。
2. **诊断**：`humanizer prompt diagnose`，读它打印的 prompt，按格式输出裁决表，写到 `.humanizer/diagnose.out.md`。审稿模式到此为止：`humanizer finish` 生成审稿报告，交付。
3. **改写**：`humanizer prompt rewrite --round 1`，按格式输出补丁、台账（bounded 还有待确认删除清单），写到 `.humanizer/rewrite-r1.out.md`。
4. **核验**：`humanizer apply --round 1`。返回码 1 表示硬失败，读打印的失败项，`humanizer prompt rewrite --round 2` 会把失败项带给你，只修失败项。最多三轮。
5. **语义判定**：`humanizer prompt judge --round <通过的那一轮>`，用一次**独立**的视角核对变更块，输出写到 `.humanizer/judge.out.md`。有失真项就再改一轮，仍失真则标为需作者确认。
6. **交付**：`humanizer finish --round <n>`。改写稿在 `.humanizer/output.md`，报告在 `.humanizer/report.md`。就地改文件模式下把 output.md 写回文件，只交付报告，不贴全文。

也可以一步跑完：`humanizer run <文件> --request "<用户原话>"`，它通过本机 `claude -p` 完成三次调用。

## 没有引擎时（降级路径）

引擎装不上或跑不起来，自己按同一套协议做，并在交付时声明「未经机械校验」：

1. 自己给全文按句编号（中文按。！？切，编号跨段连续），列出逐字项（命令、数字与单位、日期、版本、专名）。
2. 自己写一行分诊声明：体裁与依据、模式、力度、范围、声口。
3. 自己列编号问题清单（F/S 编号），每条写句号、规则、触发、裁决、修法。
4. 改写只输出句子级补丁和台账，台账里每个编号都要有一行。in-place 不删不并不拆；bounded 不并，整句空话进待确认清单；校对不动结构。
5. 改完自己按逐字项清单逐项回查，缺一项就补回。
6. 交付改写稿、改动说明、残留清单、前提声明，声明这一遍没有经过机械校验。它只保证列了的都处理了，不承诺别的。

## 五条保护铁律

不新增原文没有的事实、数字、例子、观点、来源；不丢原文有的信息和限定；不把不确定改成确定，不把相关改成因果；不动逐字项和作者的声口；不为显得像真人添加原文没有的第一人称、幽默、感受。冲突时：事实与原意 > 用户指定 > 作者声口 > 自然表达 > 原有格式。

## 三种模式与四条轴

审稿（"看看哪里像 AI"）交付裁决后的问题清单，默认不超过六条，结论只用「命中模式 N 处／无需编辑／已授权改写／不确定」；改写（"改""润色""去 AI 味""校对"）交付改写稿加改动说明与残留清单；就地改文件（点名文件）写回文件加简短报告。力度按措辞：改写、润色、校对。范围：structural（默认）、bounded（中文公开长文默认，或用户要求不删句）、in-place（用户要求保留句数）。

## 规则卡片

`skill/cards/` 由 `rules/` 生成，只在诊断步骤按命中读，不读全表。范例在 `prompts/examples/`。
